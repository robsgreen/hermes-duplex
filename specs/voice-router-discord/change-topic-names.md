# Change brief: refer to tasks by topic; numbers only behind the scenes — user-directed, 2026-11-03 (revision to draft PR robsgreen/hermes-duplex#1)

Goal: people never hear task numbers. Everything spoken names a task by its topic (a short gist of the request, e.g. "your portfolio check" / "the Tesla question"). Numbers stay internal (TaskTracker, tasks.jsonl, logs, /duplex status, tool arguments, model-only context).

1. Spoken notices (prompts/notices.py): rewrite every notice that says "Task N" to use the topic instead, e.g. started → 'Started: "how is my portfolio doing" (stock-picker).' or similar natural wording; queued → 'Queued "what about Tesla" behind "how is my portfolio doing".'; failed/cancelled/away/status summaries/which_to_cancel ("Which one: the portfolio check or the Tesla question?"). Add a short topic helper (gist with a smaller limit, ~40 chars, word-boundary cut) as the one source. Keep wording short and speakable. Model-only context (reseed history_summary / task_list, GPT-Live thinking appends, JSON task_report) may keep numbers but must also carry the topic.
2. Prompts (all three prompters + blocks.CANCEL_POLICY): tell the model to refer to tasks by what they are about and never say task numbers aloud; numbers it sees are internal ids. Remove GPT-Live's "say its number as you hand off" instruction. Realtime/Grok: `task_status` and `cancel_task` gain an optional `about` string (the user's words describing the task) alongside optional `task_id`; tell the model to pass `task_id` when it has it from a tool result, else `about`. Regenerate goldens; keep each vendor's structure.
3. Session task resolution (replace number-sniffing): resolve which task a status/cancel request means among the speaker's active tasks by, in order: explicit task_id (tool-style) → explicit "task N" in the user's words (still accepted, not advertised) → topic match of the request/`about` text against each active task's request text (simple normalized word-overlap score with a clear-winner margin) → if exactly one task is active, that one → else ambiguous: cancel asks which by topic (no stop sent); status summarizes all. Drop the assistant-context "Cancelling task N" fallback (this also resolves known issue K2). Pure function with tests: "cancel the portfolio one" with portfolio+tesla running → portfolio; "cancel that" with two running → asks; "how's the Tesla thing" → Tesla status; "cancel task 2" → 2; unrelated words with two running → asks.
4. task_status tool output (Realtime/Grok) returns JSON listing the speaker's tasks with id, topic, agent, state so the model can pass task_id next time; the spoken answer uses topics.
5. Docs: README usage (refer by topic; numbers internal), architecture.md, live-checklist items 14a/15, AGENTS.md test count. Update the PR's known-issue list in the orchestrator (not your job).
Out of scope: the other known issues (K1, K3, K4).
