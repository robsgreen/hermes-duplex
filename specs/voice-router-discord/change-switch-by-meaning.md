# Change: switch requests recognized by the router and matched by meaning (user-approved 2026-11-06)
Live test: "go to the stock trader profile" didn't switch ("go to" not a switch verb; "stock trader" not a name/alias).
1. New router choice `_switch` (like `_control`): built-in examples ("go to the … profile", "put me on …", "use the … agent", "can I talk to …", "connect me with …", "switch agents", "change profile to …"); described for Decisions/Jev; knn embeds the examples. Strong-evidence bar like _control (named constant; justify with eval); otherwise the request is a task. The deterministic parser stays first (exact phrases switch at once without the router).
2. Target resolution by meaning: a local knn match of the user's words (the request minus the switch phrasing, or the whole request) against each profile's name, aliases and description; one clear winner (named similarity bar + margin) → switch; close call → which_profile (permitted list); not permitted → switch_refused. Used for: router-detected switch requests, the switch_profile tool argument (Realtime/Grok), Discord /duplex profile, web picker frame — wherever exact/alias resolution fails today. Exact name/alias still wins first.
3. Rest after a switch ("go to stocks and check NVDA") follows existing switch-then-rest rules where the parser can split it; for router-detected switches with no clear rest, no task runs.
4. Eval: new labelled phrases for _switch (incl. "go to the stock trader profile", "use my portfolio agent", ordinary requests with "go to"/"use" that must stay tasks); report switch precision/recall and target accuracy; keep task_as_control 0 and add task_as_switch ~0.
5. Docs (README switching section, architecture, live checklist) and tests (router, session, transports).
